# Adding a game

## Does it belong here?

It has to pass all four:

1. **No equipment.** No cards, no board, no app, no shared screen. Voice, or a
   phone camera at most.
2. **No setup.** Explainable out loud in under a minute, to someone who is
   tired and lying down.
3. **Built for two.** Not scaled down from a party game.
4. **You end up closer.** By laughing, by learning something, or by having made
   a thing together. "Fun but you feel nothing afterward" is a fine game — it's
   just not one for this repo.

A game that fails #1 or #2 but is otherwise great is worth noting in the
relevant game's **Variations** section rather than adding as its own page.

## How

1. Copy [`games/_TEMPLATE.md`](../games/_TEMPLATE.md) to
   `games/your-game-name.md`. Lowercase, hyphens, no dates.
2. Fill in every section. The ones that matter most:
   - **The rules that matter** — not the full rules. The two or three rules
     that are the difference between fun and tedious. Most folk games have one
     rule everyone forgets, and it's always the one that makes the game work.
   - **Why it works** — be honest. If it's just fun, say it's just fun.
3. Add a row to the table in the [README](../README.md), in a sensible place —
   the table is loosely ordered from light to deep.
4. If it changes the calculus, update
   [`docs/choosing-a-game.md`](choosing-a-game.md).

## Style

- Second person. "You go first," not "the first player goes first."
- Short sentences. These pages get read aloud over a phone.
- Give real examples of prompts and categories. A game page with no starter
  prompts is a game nobody will play — coming up with the first prompt is the
  actual barrier, every time.
- Wrap at 80 columns.

## Credit

If a game has a known author, source, or published origin, credit it on the
game's page — a line at the bottom is enough. If it's a folk game with no
owner (most of them), say that. Don't reproduce long copyrighted lists of
prompts; link to the source and explain how to run it.
